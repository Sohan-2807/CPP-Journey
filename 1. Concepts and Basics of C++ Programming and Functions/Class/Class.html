Classes and Object-Oriented Programming

Complete reference covering OOP pillars, procedural vs object-oriented paradigms, class encapsulation, static members, `this` pointer, object arrays, self-referential classes, and object composition.

1. Concepts of OOP & Languages

Object-Oriented Programming (OOP) is a programming paradigm built around "objects" rather than "actions", and "data" rather than "logic".

Core Pillars of OOP:

  • Class & Object: A class is a user-defined blueprint; an object is an instance of a class with state and behavior.
  • Encapsulation: Binding data and functions into a single unit, hiding internal state via access specifiers.
  • Data Abstraction: Displaying only essential features to the user while hiding background implementation complexity.
  • Inheritance: Mechanism where a new class derives properties and behaviors from an existing class.
  • Polymorphism: The ability of a message or function call to be processed in more than one form (compile-time & runtime).
  • Dynamic Binding: Linking function calls to code at runtime based on the actual object type.
  • Message Passing: Objects communicate with each other by sending and receiving data through member functions.

2. Procedural vs Object-Oriented Programming Paradigms

Feature Procedural Programming (POP) e.g., C, Pascal Object-Oriented Programming (OOP) e.g., C++, Java
Focus Focuses on functions and step-by-step algorithms. Focuses on data, entities, and real-world modeling.
Program Structure Divided into small units called Functions. Divided into units called Classes and Objects.
Approach Top-Down approach. Bottom-Up approach.
Data Security Data moves freely between functions; poor security. Data is hidden (encapsulated); high security.
Inheritance / Reusability Not supported. Fully supported through class hierarchies.
Overloading Functions cannot be overloaded. Function and Operator overloading supported.

3. Reading & Writing Data Using `cin` and `cout`

C++ uses streams for I/O operations through the standard header <iostream>.

  • std::cout: Standard output stream associated with console output. Uses the stream insertion operator (<<).
  • std::cin: Standard input stream associated with the keyboard. Uses the stream extraction operator (>>).
int age;
std::string name;

std::cout << "Enter name and age: ";
std::cin >> name >> age; // Chained extraction
std::cout << "Hello, " << name << " (" << age << " yrs)\n";

4. Classes, Objects & Member Access

class Student {
private:
    int rollNo;
    double gpa;

public:
    void setData(int r, double g) {
        rollNo = r;
        gpa = g;
    }
    void display() {
        std::cout << "Roll: " << rollNo << " | GPA: " << gpa << '\n';
    }
};

int main() {
    Student s1, s2; // Class Objects
    s1.setData(101, 3.9); // Member access via dot operator (.)
    s1.display();
}

5. Inline vs Non-Inline Member Functions

Inline Member Function

Defined inside the class body. The compiler implicitly treats it as an inline function candidate.

class Math {
public:
    int square(int x) { return x * x; }
};
Non-Inline Member Function

Declared inside class, defined outside using the Scope Resolution Operator (::).

class Math {
public:
    int cube(int x);
};
int Math::cube(int x) {
    return x * x * x;
}

6. Static Data Members & Static Member Functions

  • Static Data Member: Only one copy exists for the entire class, shared by all instances. Must be defined at file scope outside the class.
  • Static Member Function: Can be invoked using the class name (ClassName::func()) without an object instance. Cannot access non-static data members or the this pointer!
class Counter {
private:
    static int count; // Declaration
public:
    Counter() { count++; }
    static int getCount() { return count; }
};

// Definition outside class:
int Counter::count = 0;

// Usage without creating an object:
std::cout << Counter::getCount();

7. The `this` Pointer

this is a constant pointer passed implicitly to all non-static member functions, holding the memory address of the invoking object (ClassName* const this).

  • Differentiates between shadowed member variables and parameters: this->val = val;
  • Returns reference to calling object to enable method chaining: return *this;

8. Array of Objects

When multiple objects of a class are needed, they can be organized into an array just like primitive data types.

Student classroom[3]; // Array of 3 Student objects

for (int i = 0; i < 3; ++i) {
    classroom[i].setData(100 + i, 3.5 + i * 0.2);
    classroom[i].display();
}

9. Self-Referential Classes

A Self-Referential class is a class that contains a pointer pointing to an object of the same class type. This is the cornerstone for implementing dynamic linked data structures like Linked Lists, Trees, and Graphs.

class Node {
public:
    int data;
    Node* next; // Pointer to an object of the same class type!

    Node(int val) : data(val), next(nullptr) {}
};

// Linking two nodes:
Node* head = new Node(10);
head->next = new Node(20);

10. Composition vs Aggregation (HAS-A Relationships)

Object relationships that represent "HAS-A" associations:

Property Composition (Strong Association) Aggregation (Weak Association)
Relationship "Part-Of" (e.g., A Car has an Engine; House has a Room). "Has-A" (e.g., A Department has a Teacher; Car has a Passenger).
Object Lifetimes Tightly bound. Destroying parent destroys the child component. Independent. Destroying parent does NOT destroy the child.
Implementation Held as direct member objects (by value): Engine engine; Held as pointers or references: Teacher* teacher;
