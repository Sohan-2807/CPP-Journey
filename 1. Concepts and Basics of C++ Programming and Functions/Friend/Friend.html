Encapsulation & Access Control

Friend Functions and Friend Classes in C++

Complete reference on controlled encapsulation bypassing, global friends, cross-class member friends, friendship rules, and stream operator overloading.

1. What is the `friend` Keyword?

In C++, encapsulation strictly restricts access to private and protected members of a class. The friend mechanism allows a class to explicitly grant access to its non-public members to specific external functions or other classes.

  • A friend function is not a member function of the class.
  • It has no this pointer.
  • It can be declared anywhere in the class (in private, protected, or public without affecting its access level).

2. Global Friend Functions

A global non-member function granted access to private state:

class Box {
private:
    double width;

public:
    Box(double w) : width(w) {}

    // Declare global friend function
    friend void printWidth(const Box& b);
};

// Definition outside class (NOTE: Do NOT use friend keyword or Box:: scope!)
void printWidth(const Box& b) {
    // Can access private 'width' directly:
    std::cout << "Width: " << b.width << '\n';
}

3. Member Function of Another Class as Friend

You can grant friendship to a specific method of another class. This requires careful forward declarations and ordering:

class TargetClass; // Forward declaration

class Inspector {
public:
    void inspect(const TargetClass& t); // Declare only
};

class TargetClass {
private:
    int secretCode = 999;

    // Grant friendship specifically to Inspector::inspect
    friend void Inspector::inspect(const TargetClass& t);
};

// Define the method after TargetClass definition is known
void Inspector::inspect(const TargetClass& t) {
    std::cout << "Secret code: " << t.secretCode << '\n';
}

4. Friend Classes

When an entire class is declared as a friend, all member functions of the friend class gain access to private and protected members of the granting class.

class Engine {
private:
    int horsepower = 450;
    bool turboActive = false;

    // Declare Car as friend class
    friend class Car;
};

class Car {
public:
    void tuneEngine(Engine& e) {
        e.horsepower += 50;     // Direct private access
        e.turboActive = true;
    }
};

5. Core Rules of Friendship

⚠️ The Three Iron Rules of C++ Friendship
  1. Friendship is NOT Symmetric (Not Mutual): If Class A declares Class B as a friend, Class B can access Class A's private members. But Class A cannot access Class B's private members unless B explicitly returns the favor.
  2. Friendship is NOT Transitive: If A is a friend of B, and B is a friend of C, A is not automatically a friend of C ("A friend of your friend is not your friend").
  3. Friendship is NOT Inherited: If Base declares F as a friend, Derived from Base does not inherit friendship with F.

6. Operator Overloading with Friends

The primary real-world use case of friend functions is overloading the stream insertion (<<) and extraction (>>) operators, where the left-hand operand is a stream object (like std::ostream), not your class object.

class Complex {
    double real, imag;
public:
    Complex(double r, double i) : real(r), imag(i) {}

    // Must be a friend/non-member because std::cout is the left operand
    friend std::ostream& operator<<(std::ostream& os, const Complex& c) {
        os << c.real << " + " << c.imag << "i";
        return os;
    }
};

// Usage: std::cout << Complex(3.0, 4.0);

7. Bridging Multiple Classes

A single friend function can be a friend of multiple classes simultaneously, acting as a clean external bridge between two distinct data representations:

class ClassB; // Forward declaration

class ClassA {
    int valueA = 10;
    friend int sumValues(const ClassA& a, const ClassB& b);
};

class ClassB {
    int valueB = 20;
    friend int sumValues(const ClassA& a, const ClassB& b);
};

int sumValues(const ClassA& a, const ClassB& b) {
    return a.valueA + b.valueB; // Accesses private data of BOTH classes
}

8. Encapsulation vs. Friend Trade-offs

Advantages Disadvantages
Enables natural operator overloading syntax (e.g. cout << obj, 2.0 * matrix). Tightly couples external entities to internal class representation.
Provides granular access without making members public to the entire world. Refactoring private variables requires rewriting all friend functions.
Allows efficient inter-class communication between tightly collaborating components (e.g. Iterator and Container). Overuse can erode the benefits of object-oriented data hiding.
