Inheritance and Polymorphism in C++

Complete guide covering base/derived relationships, access modes, multiple & hybrid inheritance, diamond problem resolution, virtual base classes, and runtime polymorphism.

1. Principles of Inheritance

Inheritance is an OOP mechanism allowing a new class (the Derived Class) to inherit attributes and behaviors from an existing class (the Base Class), modeling an IS-A relationship.

  • Base Class: The parent/superclass being inherited from.
  • Derived Class: The child/subclass extending the base class.
class Vehicle {
public:
    std::string brand = "Ford";
    void honk() { std::cout << "Beep!\n"; }
};

// Derived class inheriting publicly from Vehicle
class Car : public Vehicle {
public:
    std::string model = "Mustang";
};

2. Visibility Modes (3x3 Matrix)

The derivation mode (public, protected, or private) controls the accessibility of base class members inside the derived class and to external callers.

Base Member Access Derived Mode: public Derived Mode: protected Derived Mode: private
public Stays public Becomes protected Becomes private
protected Stays protected Stays protected Becomes private
private Hidden (Not Inherited) Hidden (Not Inherited) Hidden (Not Inherited)
📌 Rule of Thumb

Use public inheritance 99% of the time to represent true IS-A polymorphism. Use private inheritance only for composition/implementation details.

3. Types of Inheritance

1. Single Inheritance

One derived class inherits directly from one base class: A ← B

2. Multilevel Inheritance

A chain of inheritance where a derived class acts as a base for another: A ← B ← C

3. Multiple Inheritance

One derived class inherits directly from multiple base classes: (A, B) ← C

4. Hierarchical Inheritance

Multiple derived classes inherit from a single base class: A ← (B, C)

5. Hybrid Inheritance

A combination of two or more forms of inheritance (e.g., Multilevel + Multiple).

4. Multiple Inheritance & Ambiguity

When two base classes declare functions with the identical name and signature, calling it from a derived object creates an ambiguity error.

class ClassA {
public:
    void show() { std::cout << "From ClassA\n"; }
};

class ClassB {
public:
    void show() { std::cout << "From ClassB\n"; }
};

class Derived : public ClassA, public ClassB {};

int main() {
    Derived d;
    // d.show(); // COMPILE ERROR: Ambiguous call!

    // Resolution 1: Scope Resolution Operator
    d.ClassA::show();
    d.ClassB::show();
}

5. The Diamond Problem & Virtual Base Classes

Occurs when class D inherits from both B and C, which both inherit from a common base class A.

🚨 The Problem

Without intervention, object D receives two separate copies of class A's data members! This wastes memory and causes compiler ambiguity.

Solution: Virtual Base Classes

By declaring virtual public inheritance in intermediate classes B and C, the compiler ensures that only one single shared instance of class A is constructed inside D.

class A {
public:
    int data = 100;
};

// Virtual inheritance
class B : virtual public A {};
class C : virtual public A {};

class D : public B, public C {};

int main() {
    D obj;
    std::cout << obj.data; // Unambiguous and safe! Only 1 copy of A exists.
}

6. Constructor & Destructor Execution Order

  • Constructors: Base class constructor runs first, followed by Derived class constructor.
  • Destructors: Derived class destructor runs first, followed by Base class destructor (exact reverse order).
class Derived : public Base {
public:
    // Explicitly forwarding parameters to Base constructor:
    Derived(int x, int y) : Base(x) {
        // Derived constructor body
    }
};

7. Virtual Functions & Dynamic Binding

To enable runtime polymorphism (allowing a base class pointer to invoke the derived class's overridden method), declare the method as virtual in the base class.

class Shape {
public:
    virtual void draw() { std::cout << "Drawing generic shape\n"; }
    virtual ~Shape() = default; // ALWAYS declare virtual destructor in polymorphic base!
};

class Circle : public Shape {
public:
    void draw() override { std::cout << "Drawing Circle\n"; }
};

int main() {
    Shape* s = new Circle();
    s->draw(); // Dynamically dispatches to Circle::draw()!
    delete s;
}

8. `override` & `final` Specifiers (C++11)

  • override: Directs the compiler to verify that the method actually overrides a virtual method in a base class (catches typo errors).
  • final: Prohibits a class from being inherited or a virtual function from being overridden further down the hierarchy.
class LockedClass final {}; // Cannot be derived from

9. Operator Overloading (Unit IV Syllabus)

Operator overloading allows user-defined classes to redefine standard C++ operators (e.g. +, -, ++, ==) to behave naturally with class objects.

Unary Operator Overloading

Operates on a single operand (e.g., prefix ++ or negation -):

class Counter {
    int count;
public:
    Counter(int c = 0) : count(c) {}

    // Overload prefix ++:
    Counter& operator++() {
        ++count;
        return *this;
    }
};

Counter c(5);
++c; // Calls c.operator++()
Binary Operator Overloading

Operates on two operands (left operand invokes method, right is passed as argument):

class Complex {
    double r, i;
public:
    Complex(double real = 0, double imag = 0) : r(real), i(imag) {}

    // Overload +:
    Complex operator+(const Complex& other) const {
        return Complex(r + other.r, i + other.i);
    }
};

Complex c1(2, 3), c2(4, 5);
Complex c3 = c1 + c2; // c1.operator+(c2)

10. Early Binding vs Late Binding & Abstract Classes (Unit V Syllabus)

Feature Early Binding (Static / Compile-Time) Late Binding (Dynamic / Runtime)
Definition Function call resolved at compile time. Function call resolved during program execution at runtime.
Mechanism Normal member functions, function/operator overloading. Virtual functions invoked through pointers/references.
Performance Faster (zero indirection overhead). Minor runtime overhead (VPTR → VTABLE lookup).
Flexibility Rigid, fixed compile-time decisions. High extensibility and polymorphic behavior.

Abstract Classes & Pure Virtual Functions

A pure virtual function is declared with = 0. A class having at least one pure virtual function is an Abstract Class; it cannot be instantiated directly and serves purely as an interface for derived classes.

// Abstract Base Class:
class PaymentGateway {
public:
    // Pure Virtual Function:
    virtual void pay(double amount) = 0;
    virtual ~PaymentGateway() = default;
};

// Concrete Derived Class:
class CreditCardPayment : public PaymentGateway {
public:
    void pay(double amount) override {
        std::cout << "Processing Credit Card: $" << amount << '\n';
    }
};

// PaymentGateway p; // COMPILE ERROR: Cannot instantiate abstract class!
PaymentGateway* pg = new CreditCardPayment();
pg->pay(150.0); // Late binding
delete pg;

11. Aggregation and Composition (Unit IV Syllabus)

While inheritance models IS-A, aggregation and composition model HAS-A associations:

  • Composition (Part-Of): Strong ownership. Child lifetime is strictly controlled by parent. (e.g. Car has an Engine; when Car is destroyed, Engine dies).
  • Aggregation (Has-A): Weak relationship. Child lifetime is independent of parent. (e.g. College aggregates Students; students exist even if college shuts down).
