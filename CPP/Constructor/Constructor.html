Object Lifecycle

Constructors and Destructors in C++

Complete reference on object construction, member initialization lists, deep vs shallow copying, move semantics, RAII, and object destruction.

1. Manager Functions: What is a Constructor?

In C++, constructors and destructors are formally classified as Manager Functions because they manage the allocation, initialization, lifetime, and clean destruction of resources and memory associated with class instances.

A constructor is automatically invoked when an object is created:

  • Shares the exact name of the enclosing class.
  • No return type (not even void).
  • Cannot be const, static, or virtual.

2. Default Constructors & Constructors with Default Arguments

A default constructor accepts no parameters. A constructor with default arguments can be called with fewer or zero arguments:

class Box {
    int length, width, height;
public:
    // Constructor with Default Arguments (acts as Default & Parameterized!):
    Box(int l = 1, int w = 1, int h = 1)
        : length(l), width(w), height(h) {}
};

Box b1;             // Uses defaults: 1, 1, 1
Box b2(10);         // 10, 1, 1
Box b3(10, 20, 30); // 10, 20, 30

3. Dynamic Constructors

A Dynamic Constructor uses the new operator inside the constructor body to allocate memory dynamically on the heap at runtime.

class StringHolder {
    char* str;
    int length;
public:
    // Dynamic Constructor:
    StringHolder(const char* s) {
        length = strlen(s);
        str = new char[length + 1]; // Heap allocation
        strcpy(str, s);
    }
    ~StringHolder() {
        delete[] str; // Frees dynamically allocated memory
    }
};

3. Parameterized Constructors

Constructors that take arguments to initialize data members with custom initial values.

class Rectangle {
    int width, height;
public:
    Rectangle(int w, int h) {
        width = w;
        height = h;
    }
};

// Invocation styles:
Rectangle r1(10, 20);      // Direct initialization
Rectangle r2{10, 20};      // Uniform list initialization (C++11)

4. Member Initializer Lists (Best Practice)

Initializes member variables before the constructor body executes, placed between the constructor parameter list and opening brace.

class Student {
    const int rollNumber; // MUST use initializer list
    std::string& refName; // References MUST use initializer list
    std::string branch;

public:
    Student(int r, std::string& name, std::string b)
        : rollNumber(r), refName(name), branch(b) {
        // Constructor body
    }
};
💡 Why Member Initializer Lists Win

Assigning inside the constructor body first calls the default constructor for members, then calls the copy assignment operator (double work). Initializer lists directly construct members with the given arguments.

5. Copy Constructors

Initializes a new object as a copy of an existing object of the same class. Signature: ClassName(const ClassName& other).

class Point {
public:
    int x, y;
    Point(int a, int b) : x(a), y(b) {}

    // Copy Constructor
    Point(const Point& other) : x(other.x), y(other.y) {
        std::cout << "Copy constructor called\n";
    }
};

Point p1(5, 10);
Point p2 = p1; // Copy constructor triggered
Point p3(p1);  // Copy constructor triggered

6. Shallow Copy vs Deep Copy

When a class owns dynamically allocated memory (pointers), understanding shallow vs deep copy is vital:

❌ Shallow Copy (Default)

Copies member variables bit-by-bit. If a member is a pointer, only the memory address is copied! Both objects point to the same memory location.

Bug: When both objects destruct, they free the same address (Double Free Crash!).

✅ Deep Copy (Custom)

Allocates fresh dynamic memory for the new object and copies the actual underlying data over.

class Buffer {
    int* data;
public:
    Buffer(int val) {
        data = new int(val);
    }
    // Deep Copy Constructor
    Buffer(const Buffer& other) {
        data = new int(*other.data);
    }
    ~Buffer() { delete data; }
};

7. Move Constructors (C++11)

Instead of deep-copying expensive heap buffers from temporary objects (rvalues), a move constructor steals the pointers from the source object and nulls them out.

class DynamicArray {
    int* arr;
    size_t size;
public:
    // Move Constructor (rvalue reference &&)
    DynamicArray(DynamicArray&& other) noexcept
        : arr(other.arr), size(other.size) {
        // Reset source object so its destructor won't free stolen memory
        other.arr = nullptr;
        other.size = 0;
    }
};

8. Delegating Constructors

C++11 allows a constructor to call another constructor in the same class within its initializer list to eliminate redundant initialization code:

class Circle {
    double radius;
    std::string color;
public:
    // Target Constructor
    Circle(double r, std::string c) : radius(r), color(c) {}

    // Delegating Constructor
    Circle() : Circle(1.0, "red") {}
};

9. The `explicit` Keyword

A single-argument constructor can be used by the compiler for implicit type conversion. Prefixing it with explicit prevents unexpected accidental conversions.

class SmartInt {
public:
    explicit SmartInt(int x) {}
};

void test(SmartInt s);

// test(42);       // COMPILE ERROR: Implicit conversion forbidden!
test(SmartInt(42)); // OK: Explicit construction

10. Destructors, RAII & Virtual Destructors

A destructor is invoked automatically when an object's lifetime ends (leaves stack scope, or deleted with delete).

  • Same name as class preceded by tilde: ~ClassName().
  • Takes no arguments, cannot be overloaded.
  • Destruction Order: Exact reverse of construction order!

Virtual Destructors in Polymorphic Base Classes

If a base class has any virtual functions, its destructor must be declared virtual. Without a virtual destructor, deleting a derived object through a base pointer causes undefined behavior and leaves the derived part of the object leaked!

class Base {
public:
    virtual ~Base() { std::cout << "Base destroyed\n"; }
};

class Derived : public Base {
    int* arr = new int[50];
public:
    ~Derived() override {
        delete[] arr;
        std::cout << "Derived array freed\n";
    }
};

Base* b = new Derived();
delete b; // Calls ~Derived() first, then ~Base() cleanly!
📌 RAII (Resource Acquisition Is Initialization)

Acquire resources (file handles, heap memory, mutex locks, sockets) in constructors; release them cleanly in destructors. Guarantees zero resource leaks even if exceptions occur.

11. Rule of Three / Five / Zero

  • Rule of Three (C++98): If you define a custom Destructor, Copy Constructor, or Copy Assignment Operator, you almost certainly need to define all three.
  • Rule of Five (C++11): Adding move semantics: Destructor, Copy Constructor, Copy Assignment, Move Constructor, Move Assignment.
  • Rule of Zero (Modern C++): Design classes using standard types (e.g. std::unique_ptr, std::vector, std::string) that manage their own resources, so you don't need to manually write any custom destructors or copy/move operations!
