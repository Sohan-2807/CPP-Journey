Pointers in C++: Complete Guide

Exhaustive guide covering memory addressing, dereferencing, pointer categories, const correctness, pointer-to-members, heap management, and modern smart pointers.

1. Pointer Fundamentals

A pointer is a variable whose value is the memory address of another variable.

  • & (Address-Of Operator): Retrieves the memory address of an lvalue.
  • * (Dereference / Indirection Operator): Accesses or mutates the value stored at the address pointed to.
int var = 50;
int* ptr = &var; // ptr stores memory address of var

std::cout << "Address: " << ptr << '\n';   // e.g., 0x7ffd9b8a
std::cout << "Value: " << *ptr << '\n';     // 50

*ptr = 100; // Direct mutation of 'var' through pointer
std::cout << var; // Outputs 100

2. Null, Void, Wild & Dangling Pointers

1. Null Pointer (`nullptr`)

Points to no valid memory location. In modern C++, always prefer nullptr (type std::nullptr_t) over NULL or 0.

int* p = nullptr;
if (p != nullptr) { *p = 10; }
2. Void (Generic) Pointer (`void*`)

Can hold the address of any data type. Cannot be directly dereferenced without an explicit cast.

int x = 10;
void* v = &x;
int* intPtr = static_cast<int*>(v);
3. Wild Pointer (Uninitialized)

A pointer declared without an initial address. Holds arbitrary garbage; dereferencing it triggers instant UB or crashes.

int* badPtr; // DANGER! Wild pointer
// Always initialize: int* p = nullptr;
4. Dangling Pointer

Points to a memory location that has already been deallocated or freed.

int* ptr = new int(5);
delete ptr;       // Memory freed
// ptr is now dangling!
ptr = nullptr;    // Fix: clear immediately
5. Pointer to Pointer (`**`)

A pointer that stores the address of another pointer (double indirection).

int val = 100;
int* p1 = &val;   // Points to val
int** p2 = &p1;  // Points to p1

std::cout << **p2; // Outputs 100

3. Classes Containing Pointers (Unit II Syllabus)

When a class member is a pointer pointing to dynamically allocated memory, the class must implement a custom Destructor to free heap memory, along with a custom Deep Copy Constructor and Copy Assignment Operator (Rule of Three):

class ArrayContainer {
private:
    int* data;
    int size;

public:
    ArrayContainer(int s) : size(s) {
        data = new int[size]; // Dynamic allocation inside constructor
    }

    // Deep Copy Constructor
    ArrayContainer(const ArrayContainer& other) : size(other.size) {
        data = new int[size];
        for (int i = 0; i < size; ++i) data[i] = other.data[i];
    }

    ~ArrayContainer() {
        delete[] data; // Free heap memory
    }
};

3. Pointer & Const Variations (The "Clockwise/Spiral Rule")

Read declarations backwards (from right to left) to understand const binding:

Declaration Type Can Change Pointed Value (*ptr = ...)? Can Reassign Address (ptr = ...)?
int* ptr; Non-const pointer to non-const int ✅ Yes ✅ Yes
const int* ptr;
(or int const* ptr;)		 Pointer to Constant (data is read-only) ❌ No ✅ Yes
int* const ptr = &x; Constant Pointer (address is locked) ✅ Yes ❌ No
const int* const ptr = &x; Constant Pointer to Constant ❌ No ❌ No

4. Pointer Arithmetic

Pointer arithmetic operates in units of the underlying data type's byte size:

  • ptr + 1 advances the address by 1 * sizeof(*ptr) bytes (e.g., +4 bytes for int, +8 bytes for double).
  • ptr2 - ptr1 yields the number of elements between them (of type std::ptrdiff_t).

5. Pointers & Arrays

int arr[5] = {12, 45, 7, 90, 23};
int* p = arr; // Decays to &arr[0]

// Finding maximum value using pointers:
int maxVal = *p;
for (int i = 1; i < 5; ++i) {
    if (*(p + i) > maxVal) {
        maxVal = *(p + i);
    }
}
std::cout << "Max: " << maxVal; // 90

6. Pointers to Objects & Arrow (`->`)

When accessing members of an object through a pointer, the arrow operator -> is shorthand for dereferencing followed by the dot operator: ptr->member == (*ptr).member.

class Player {
public:
    int score = 100;
    void levelUp() { score += 50; }
};

Player* p = new Player();
p->levelUp();
std::cout << p->score; // 150
delete p;

7. Pointers to Class Members

C++ allows defining pointers that point specifically to a class data member or member function across instances:

class Sample {
public:
    int x = 42;
    void print() { std::cout << x << '\n'; }
};

// Pointer to Data Member:
int Sample::*dPtr = &Sample::x;

// Pointer to Member Function:
void (Sample::*fnPtr)() = &Sample::print;

Sample obj;
Sample* objPtr = &obj;

std::cout << obj.*dPtr;    // Access with .* operator
(objPtr->*fnPtr)();        // Invoke with ->* operator

8. Modern Smart Pointers (C++11, ``)

Smart pointers eliminate manual delete calls by wrapping raw pointers in RAII objects that automatically deallocate memory when out of scope.

`std::unique_ptr` (Exclusive)

Sole ownership. Cannot be copied, only moved. Zero overhead compared to a raw pointer.

auto p1 = std::make_unique<int>(42);
auto p2 = std::move(p1); // Ownership transferred
`std::shared_ptr` (Reference Counted)

Shared ownership. Destroys the object when the internal reference count drops to 0.

auto s1 = std::make_shared<int>(100);
auto s2 = s1; // Ref count becomes 2
`std::weak_ptr` (Non-Owning Observer)

Observes a shared_ptr without increasing reference count; breaks circular reference memory leaks.

9. Memory Allocation Failures & Leaks (Unit V Syllabus)

When the heap is exhausted, dynamic memory allocation fails. Standard C++ handles this via exceptions or the std::nothrow specifier:

1. Exception Handling (`std::bad_alloc`)

By default, if new cannot allocate memory, it throws an exception of type std::bad_alloc:

try {
    int* hugeArray = new int[100000000000ULL];
} catch (const std::bad_alloc& e) {
    std::cerr << "Allocation failed: " << e.what() << '\n';
}
2. Non-Throwing `new (std::nothrow)`

Returns nullptr instead of throwing an exception on failure:

int* ptr = new (std::nothrow) int[100000000000ULL];
if (ptr == nullptr) {
    std::cerr << "Memory allocation failed cleanly!\n";
}
🚨 What is a Memory Leak?

A memory leak occurs when heap memory is allocated with new or malloc() but is never deallocated with delete or free(), and all pointers to that memory are lost. Over time, memory leaks consume RAM and crash the system.

10. Memory Leaks & Best Practices

  1. Every new must have a matching delete; every new[] must have a matching delete[].
  2. Set pointers to nullptr immediately after deleting them to avoid accidental reuse.
  3. Never return pointers to local automatic (stack) variables.
  4. Prefer std::unique_ptr and std::make_unique over raw new in modern C++.
